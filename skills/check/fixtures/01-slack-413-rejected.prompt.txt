Sam — I went through #485 while digging into the 413 outage and think there's a gap worth closing before it lands. The detection logic is right; the three-dot diff and `MDRT` both hold up, and it would have caught the `0001` edit. But neither enforcement surface actually blocks today: the prek hook does run in CI via `mise run lint`, except `ci.yaml`'s lint job checks out at `fetch-depth: 1`, so `origin/master` never resolves, the script takes its defaulted-base skip and exits 0 — and since prek prints nothing for a passing hook, the required check goes green having evaluated nothing. `migrations-immutable` itself isn't in master's required checks, so its red X doesn't block the merge button. Net effect is that a PR editing a merged migration gets a green required check affirmatively claiming the migrations gate passed, which is worse than not having the gate at all. One command confirms it — `mise run lint` on your branch, grep for `skipping local check`. Simplest fix is probably to make the workflow required and `--skip migrations-append-only` in `.mise.toml`, since the workflow already does it right with the explicit base and `fetch-depth: 0`. One thing to sort before it goes required, though: `lockstep.rs` does an `include_str!` on `0009_feature_flags.sql` and asserts against its text, so the next person adding an enum variant gets a compile error telling them to edit `0009` and a gate refusing the edit — and writing a new migration instead doesn't help, because lockstep still reads `0009`. Happy to write any of this up as tickets if useful.
